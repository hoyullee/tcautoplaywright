- **이력서 페이지**: GNB의 이력서 탭을 클릭하면 진입하는 페이지 (로그인 여부에 따라 URL 다름)
- **교육이벤트**: GNB의 교육•이벤트 탭을 클릭하면 진입하는 페이지
- **콘텐츠**: GNB의 콘텐츠 탭을 클릭하면 진입하는 페이지
- **소셜**: GNB의 소셜 탭을 클릭하면 진입하는 페이지
- **프리랜서**: GNB의 프리랜서 탭을 클릭하면 새 페이지에서 진입되는 페이지
- **포지션 상세 페이지**: 탐색 페이지에서 포지션 카드를 선택하면 진입되는 페이지 (URL 패턴: `https://www.wanted.co.kr/wd/{포지션ID}`)
- **GNB**: Global Navigation Bar, 페이지 상단 글로벌 네비게이션 바
- **LNB**: Local Navigation Bar, 페이지 좌측 또는 서브 네비게이션 바

## 코드 작성 규칙

### 필수 구조
```python
import sys
from playwright.async_api import async_playwright
import asyncio
import os
import pytest

TEST_EMAIL = "..."
TEST_PASSWORD = "..."

@pytest.mark.asyncio
async def test_main():
    async with async_playwright() as p:
        browser = await p.chromium.launch(headless=True)
        context = await browser.new_context(
            locale='ko-KR',
            timezone_id='Asia/Seoul'
        )
        page = await context.new_page()

        try:
            os.makedirs('screenshots', exist_ok=True)
            await page.goto('URL', timeout=30000)
            await page.wait_for_load_state('domcontentloaded')

            # 테스트 로직

            await page.screenshot(path='screenshots/<테스트 파일명>_success.png')
            print("AUTOMATION_SUCCESS")
            return True

        except Exception as e:
            await page.screenshot(path='screenshots/<테스트 파일명>_failed.png')
            print(f"AUTOMATION_FAILED: {e}")
            raise  # pytest가 FAILED로 인식하도록 반드시 re-raise

        finally:
            await browser.close()

if __name__ == "__main__":
    result = asyncio.run(test_main())
    sys.exit(0 if result else 1)
```

3. `page.locator('css-selector')`

### hover로만 노출되는 버튼 처리 패턴
마우스 hover 시에만 나타나는 버튼(예: 카드 위의 더보기/3점 버튼)은 아래 순서로 처리:
```python
# 1. Playwright hover 사용 (mouse.move 대신)
await target_element.hover()
await page.wait_for_timeout(500)

# 2. hover 후 버튼이 visible 상태가 될 때까지 대기
btn = target_element.locator('[aria-label="더보기"]')
await btn.wait_for(state='visible', timeout=5000)
await btn.click()

# 3. 위 방법 실패 시 JS로 강제 클릭 (hover 없이도 동작)
await page.evaluate("""(el) => {
    el.dispatchEvent(new MouseEvent('mouseover', {bubbles: true}));
    el.dispatchEvent(new MouseEvent('mouseenter', {bubbles: true}));
}""", await target_element.element_handle())
await page.wait_for_timeout(500)
await btn.click(force=True)
```

### 방해 팝업 처리 규칙 (반드시 준수)

검증 대상이 **아닌** 팝업·모달·배너가 화면을 가려 클릭이 막히는 경우가 있다.
(예: 로그인 상태로 탐색 홈 진입 시 뜨는 '희망 근무지 설정' 팝업)

- 이런 방해 요소를 **스크립트 안에서 직접 닫는 코드를 작성하지 말 것**
- 반드시 공용 헬퍼 `ui_helpers.dismiss_optional_popups(page)` 를 호출할 것
- 호출 위치: 페이지 진입 직후, 해당 TC 의 실제 검증을 시작하기 전

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parents[2]))
from ui_helpers import dismiss_optional_popups

await page.goto('URL', timeout=30000)
await page.wait_for_load_state('domcontentloaded')
await dismiss_optional_popups(page)   # 검증 대상이 아닌 팝업 정리
# 여기부터 이 TC 의 실제 검증
```

**헬퍼에 아직 등록되지 않은 새 팝업을 만난 경우**
1. `ui_helpers.py` 의 `POPUPS` 목록에 한 줄 추가한다
   `{'name': '팝업 이름', 'has_text': '식별 텍스트', 'button': '닫기 버튼 이름'}`
2. 스크립트에는 `dismiss_optional_popups(page)` 호출만 남긴다
3. 스크립트 안에 개별 닫기 코드를 남기지 않는다

**예외 — 팝업 자체가 검증 대상인 TC**
확인사항/기대결과가 그 팝업의 노출이나 동작을 다루는 경우에는 헬퍼를 쓰지 않는다.
그 TC 안에서 직접 노출을 확인하고 닫는다. (헬퍼가 먼저 닫으면 검증할 대상이 사라진다)

### 스크린샷 규칙 (반드시 준수)
- **TC당 스크린샷은 1장만** 허용
- **파일명은 테스트 스크립트 파일명과 반드시 일치**시킨다. 순번(NO)을 쓰지 않는다.
  - 테스트 파일이 `test/CAREERSHOME/test_CAREERSHOME_004_success.py` 라면
  - 성공 시: `screenshots/test_CAREERSHOME_004_success.png`
  - 실패 시: `screenshots/test_CAREERSHOME_004_failed.png`
- 경로는 변수나 f-string 없이 문자열 리터럴로 그대로 적는다
- 중간 단계(페이지 로드, 버튼 클릭 등) 스크린샷 절대 금지
- `page.screenshot()`은 try 블록 마지막(성공 확정 후)과 except 블록(실패 확정 후) 각각 1회씩만 호출

### page.evaluate() 성능 규칙

> ⚠️ 이 규칙은 **`page.evaluate()` 내부 JS 코드**에만 적용됩니다.
> Playwright 로케이터(`page.locator('[class*="..."]')`)는 해당 없음.

`page.evaluate()` 내부의 `querySelectorAll`에서 `[class*="..."]` 셀렉터는 DOM 전체를 순회하므로 **가능하면 시맨틱 셀렉터로 대체**하세요.

#### 셀렉터 대체 우선순위 (evaluate 내부)
| 상황 | 느린 방식 | 빠른 대체 |
|------|-----------|-----------|
| 체크박스 탐색 | `[class*="check"]` | `input[type="checkbox"], [role="checkbox"]` |
| 다이얼로그/모달 탐색 | `[class*="modal"]` | `[role="dialog"]` |
| 버튼 탐색 | `[class*="button"]` | `button, [role="button"]` |

> ⚠️ `[class*="overlay"]`는 로딩 스피너·배경 딤 등 다이얼로그가 아닌 요소에도 사용되므로 `[role="dialog"]`로 대체하지 말 것. 오버레이를 찾아야 한다면 목적에 맞는 구체적 셀렉터를 사용하세요.
> 시맨틱 속성이 없는 요소는 `class*=` 사용을 허용하되, `.slice(0, N)`으로 처리 수를 제한하세요.

#### getBoundingClientRect() 규칙
`getBoundingClientRect()`는 호출마다 레이아웃 재계산(reflow)을 강제하므로:
```javascript
// 🚫 지양 — 매칭 요소 전체에 getBoundingClientRect 호출
[...document.querySelectorAll('button')].map(el => {
    const rect = el.getBoundingClientRect();
    return { visible: rect.width > 0 };
});

// ✅ 권장 — slice로 상한 제한 후 처리
[...document.querySelectorAll('button')].slice(0, 30).map(el => {
    const rect = el.getBoundingClientRect();
    return { visible: rect.width > 0 };
});
```

**규칙 요약:**
- `querySelectorAll` + `.map()` + `getBoundingClientRect()` 조합 시 반드시 `.slice(0, N)` 선행 (체크박스: 20개, 버튼: 30개 권장)
- 시맨틱 속성(`role`, `type`, `tag`)이 있는 경우 `class*=` 대신 그것을 우선 사용

### 절대 금지
- `sys.stdout = io.TextIOWrapper(...)` 사용 금지 — pytest stdout 캡처를 파괴함
- 중간 단계 스크린샷 추가 금지 (step1, step2, login_page 등 이름의 스크린샷)
- `wait_for_load_state('networkidle')` 사용 금지 — wanted.co.kr은 백그라운드 요청이 지속되어 30초 timeout 발생. 반드시 `'domcontentloaded'` 사용
